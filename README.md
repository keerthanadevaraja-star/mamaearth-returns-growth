# Mamaearth Returns & Growth Intelligence Pipeline

An end-to-end, three-layer data pipeline that proves — not estimates — where returns
are eating into Mamaearth's margins. Each layer feeds the next: the **SQL** relational
store holds the raw orders, the **Python/pandas** layer cleans that data and computes the
verified numbers, and the **GenAI narrator** turns only those verified numbers into a
business narrative for regional ops and finance heads.

> No layer reports a number it did not itself compute or receive from the layer before it.
> `narrator/findings.json` is written by the Python layer, so the narrative can never drift
> from the analysis.

## Prerequisites

- Python 3.9+ with `pandas`, `numpy`, `matplotlib`
  (`pip install pandas numpy matplotlib`)
- SQLite (the `sqlite3` CLI, or Python's built-in `sqlite3` module)
- Optional for the online narrator path: `pip install google-genai` and a **free**
  Gemini API key from Google AI Studio (free usage tier). The pipeline is fully
  gradable **without** any key via the offline fallback.

## How the layers connect

```
data/*.csv ──> sql/schema.sql + seed_data.sql ──> sql/reports.sql   (Part 1: raw store & reports)
data/*.csv ──> analysis/clean_and_eda.py ──> narrator/findings.json (Part 2: cleaned, verified numbers)
            └> analysis/visualize.py ──> visualizations/*.png
narrator/findings.json ──> narrator/generate_narrative.py ──> sample_output.txt (Part 3: narrative)
```

Part 1 and Part 2 both read the same raw `data/*.csv` and can be run in either order.
Part 3 depends on `narrator/findings.json`, which Part 2 produces.

## Run order

### 1. SQL relational layer (Part 1)

Load the schema, seed the data, then run the reports against the **raw** loaded data:

```bash
# Using the SQLite CLI, from the repo root:
sqlite3 mamaearth.db < sql/schema.sql
sqlite3 mamaearth.db < sql/seed_data.sql
sqlite3 mamaearth.db < sql/reports.sql
```

After loading you can confirm: `SELECT COUNT(*) FROM customers;` → 45,
`products` → 16, `orders` → 180. `seed_data.sql` loads blank `discount_pct` / `rating`
cells as SQL `NULL` (not empty strings), so `COUNT(rating)` correctly returns 165.
Each query's exact expected output is pasted as a comment directly above it in
[sql/reports.sql](sql/reports.sql).

> `seed_data.sql` is generated from `data/*.csv`; regenerating it reproduces the same
> INSERTs. All cleaning happens in Part 2's Python — the CSVs are never hand-edited.

### 2. Python analysis layer (Part 2)

```bash
python analysis/clean_and_eda.py   # prints every intermediate result; writes narrator/findings.json
python analysis/visualize.py       # saves the two PNGs into visualizations/
```

`clean_and_eda.py` standardizes payment-method casing, drops the 5 duplicate orders
(`O0176`–`O0180`), imputes missing `discount_pct` (→0) and `rating` (→median 3.0),
reconciles the cleaned revenue (₹97,358.30) against Part 1's raw ₹99,860.20 (the
₹2,501.90 delta is exactly the 5 duplicates), flags the 2 IQR quantity outliers,
tests the COD-return hypothesis, segments by payment × city tier, runs correlations,
and builds the outlier-corrected monthly series. **Its final step writes
[narrator/findings.json](narrator/findings.json)** so Part 3 reads only verified numbers.

### 3. GenAI narrator layer (Part 3)

The narrator reads `narrator/findings.json` and produces the SCR
(Situation–Complication–Resolution) narrative.

```bash
# Offline path — no key, no network, fully deterministic (default when no key is set):
python narrator/generate_narrative.py

# Online path — set a FREE Gemini key first, then run the same command:
#   PowerShell:  $env:GEMINI_API_KEY="your-free-key"; python narrator/generate_narrative.py
#   bash:        GEMINI_API_KEY="your-free-key" python narrator/generate_narrative.py
```

- With **no key** (or if the Gemini call errors), it falls back to
  `generate_scr_narrative_offline()` — zero config, same return shape, same numbers.
- The request is locked to `temperature=0.0`, an explicit `max_output_tokens`, and a
  `timeout ≥ 10s`, wrapped in try/except so the caller never sees a raw exception.
- A checker asserts all five required figures (97,358.30 · 44.4 · 54.5 · 2,501.90 ·
  March + 20,318.90) appear in the narrative and prints a pass/fail line per figure.
- The produced narrative is saved to [narrator/sample_output.txt](narrator/sample_output.txt),
  which is what the grader verifies (LLM output is not byte-deterministic).

## Verified headline findings

- Cleaned revenue **₹97,358.30** vs raw **₹99,860.20** — the **₹2,501.90** gap is exactly
  the 5 duplicate orders removed, not the imputation.
- **COD return rate 44.4%** — about 3× CARD (14.7%) and well above UPI (18.9%).
- Highest-risk segment: **COD × Tier-2 cities at 54.5%** (COD risk is not uniform across tiers).
- **March 2026** is the true peak month (**₹20,318.90**); January only *looked* like the
  peak (₹29,582.10) because of two bulk outlier orders — corrected it is just ₹11,637.10.
- "Higher discounts reduce returns" is **busted** (discount vs returned r ≈ −0.09, negligible).
